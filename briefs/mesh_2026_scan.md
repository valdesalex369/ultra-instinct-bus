## 1. Agent-to-Agent Protocol Landscape (2026)

### 1.1 Google A2A (Agent2Agent)

- **Origins & governance:** Announced by Google 2025-04-09 with 50+ launch partners (Atlassian, Salesforce, SAP, LangChain, PayPal, etc.); donated to the Linux Foundation 2025-06-23 (Apache 2.0). https://techiehub.blog/what-is-the-a2a-protocol/ ; https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year

One source (2026-06-26) reports v1.2 with cryptographically signed cards. https://techiehub.blog/what-is-the-a2a-protocol/ ; https://rywalker.com/research/google-a2a ; https://ailearningguides.com/agent2agent-protocol-150-production-deployments-v12/ ; https://www.boldare.com/blog/agent-communication-protocol-acp-explained-what-it-is-and-why-it-matters/
- **Adoption (LF press release, 2026-04-09):** 150+ supporting organizations; production deployments in supply chain, financial services, insurance, IT operations; native integration in Azure AI Foundry, Copilot Studio, Amazon Bedrock AgentCore, Google Cloud; 22,000+ GitHub stars; official SDKs in Python, JavaScript, Java, Go, .NET. https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year ; https://techiehub.blog/what-is-the-a2a-protocol/
- **Named production users:** Salesforce Agentforce exposes custom agents as A2A endpoints; SAP Joule delegates to partner A2A agents; ServiceNow Now Assist registers A2A agents as skills; Atlassian Rovo agents speak A2A natively. Caveat: multiple independent analysts note most in-the-wild A2A usage is still PoC-level outside enterprise platform ecosystems; "150 supporting orgs" ≠ deep production retention. https://pickaxe.co/post/mcp-vs-a2a-protocol ; https://futureagi.com/blog/mcp-vs-a2a-2025/ ; https://www.glukhov.org/ai-systems/comparisons/a2a-protocol-2026-adoption/
- **Foundation move:** On 2026-08-17 Google moved A2A under the **Agentic AI Foundation (AAIF)** — the same Linux Foundation body holding MCP — completing consolidation of the five major agent standards (MCP, A2A, AGENTS.md, goose, AGNTCY) under one vendor-neutral org. https://santageai.com/news/2026/08/24/ai-agent-protocols-one-foundation ; https://harnessrouter.ai/guides/a2a-protocol
- **Security surface:** A2A is by design an inbound delegation surface; recommended posture in 2026 guidance is OAuth 2.0 client-credentials or mTLS, authorization re-validated at every interaction (not just discovery), minimum-scope Agent Card permissions, signed cards. Criticism: signed cards optional; agents are opaque by design. https://techiehub.blog/what-is-the-a2a-protocol/ ; https://o-mega.ai/articles/mcp-vs-a2a-in-2026-which-agent-protocol-to-use
- **Google also launched an A2A Agent Marketplace** in Google Cloud Marketplace (April 2026) with natural-language agent discovery. https://agentmarketcap.ai/blog/2026/04/12/gemini-a2a-agent-marketplace-enterprise-discovery

### 1.2 Anthropic MCP

- **Status:** Released by Anthropic November 2024; donated to the AAIF at its formation 2025-12-09 (founding stewards: Anthropic, OpenAI, Block). https://santageai.com/news/2026/08/24/ai-agent-protocols-one-foundation ; https://godwinavodagbe.com/a2a-mcp-production-interoperable-agents/

- **Current spec:** Date-based versioning. Spec `2026-07-28` (published 2026-07-28) adopts a **stateless core** and an extensions framework; deprecates Roots, Sampling, and Logging. Prior revision 2025-11-25. Known migration costs: Python SDK v2 rewrite, stateless-transport redeployment, skills-over-MCP standardization. https://ecorpit.com/mcp-vs-a2a-enterprise-agent-protocol-decision-2026/ ; https://kodekloud.com/blog/a2a-vs-mcp-agent-communication-protocols-explained-for-devops/ ; https://www.chooseai.net/news/3603/ ; https://www.partitech.com/en/technical-blog-article/mcp-a2a-and-agntcy-understanding-the-interoperability-of-ai-agents-in-2026

## 2. Git/File Blackboard & Async Agent Message-Bus Patterns (Real-World)

### 2.1 Shipping systems

- **Beads (Steve Yegge):** git-backed, agent-native issue tracker / memory system. Issues stored as JSONL in `.beads/beads.jsonl`, local SQLite cache, **hash-based IDs (`bd-a1b2`) explicitly designed to prevent merge conflicts across parallel agents**, 4 dependency types, `bd remember` persistent memory; later versions embed Dolt (git-versioned SQL) in-process or against `dolt sql-server`. ~23–24K GitHub stars; 130K+ lines of Go, "100% vibe coded." Solves the "50 First Dates" problem (agents have no memory between sessions). Has its own agent messaging with threading and ephemeral lifecycle. Per-harness setup needed (`bd setup claude|codex|factory|mux|cursor`). https://tianpan.co/forum/t/multi-agent-coding-at-scale-yegges-beads-system-produces-12k-lines-day-but-dora-says-9-more-bugs/692 ; https://mikemason.ca/writing/ai-coding-agents-jan-2026/ ; https://juanjofuchs.github.io/ai/2026/05/12/why-i-built-yet-another-agent-mail-tool.html
- **Gas Town (Yegge, open-sourced 2026-01-01, MIT):** multi-agent orchestrator running 20–30 parallel coding agents (Claude Code, Copilot, Codex, Gemini) via tmux + **git worktrees as the "propulsion mechanism"** (each unit of work = a worktree with persistent state surviving agent restarts). Role hierarchy: Mayor (coordinator), Polecats (ephemeral workers), Refinery (merge-queue agent), Witness (per-rig monitor), Deacon (cross-rig patrol), Dogs (maintenance), human Overseer; three-tier watchdog chain (daemon→Boot→Deacon); escalation CLI (`gt escalate`). Built on Beads as control+data plane; "molecules" = sequenced atomic task chains backed by git, persistent across crashes. v1.0 2026-04-03; v1.2.1 June 2026; ~16K stars; hosted version "Gas Town by Kilo" GA May 2026; **Wasteland** project federates multiple Gas Towns into a shared network. https://chadgrant.github.io/dark-factories/ ; https://rywalker.com/research/gastown ; https://github.com/gastownhall/gastown ; https://webdirections.org/blog/how-long-is-your-loop/
- **Gas City (2026-04-24, v1.2.1 by June 2026):** Gas Town decomposed into an orchestration-builder SDK — declarative TOML "packs" for arbitrary agent topologies, runtime providers for Claude Code, Codex, Gemini CLI, OpenCode (Grok Build, Groq, Cerebras attachable), on the Beads + Dolt "MEOW stack." Every agent action lands in a git-versioned database (forensic audit trail). HN reception "overwhelmingly skeptical of the orchestrator-of-orchestrators premise" (901 stars in 7 weeks). https://rywalker.com/research/gas-city ; https://nevercodealone.de/de/vibe-coding/vibe-coding-modelle/gascity-orchestration-sdk-multi-agent-vibe-coding-2026
- **OpenAI Symphony (2026-04-27):** open spec for issue-tracker-as-control-plane (§1.5) — the closest vendor-official artifact to "repo/tracker as async message bus": agents read issues, write state transitions/comments/PR links, end at workflow-defined handoff states like `Human Review`. https://openai.com/index/open-source-codex-orchestration-symphony/
- **GitHub `agent-handoffs` topic (2026):** a cluster of small OSS tools for **bounded handoffs via explicit file packets**: "explicit file packets, evidence receipts, controller-side verification," "local workflow state, context handoffs, strict human review gates," "verify what survives when one AI agent hands work to the next." https://github.com/topics/agent-handoffs
- **Agent mail / mailbox tools:** MCP-based agent mail (mcp_agent_mail, mailbox-mcp) exists; a documented pain point (May 2026) is configuring the same MCP server across 3+ harness config formats (`.mcp.json`, `~/.codex/config.toml`, `~/.gemini/settings.json`) — motivating single-file mailbox tools instead. https://juanjofuchs.github.io/ai/2026/05/12/why-i-built-yet-another-agent-mail-tool.html
- **Blackboard pattern in frameworks:** blackboard = shared memory every agent reads/writes; shipped implementations use SQL tables with agent_role + confidence + embeddings (no message bus), or message-bus + vector-store + locking. Agentropic (Rust) implements a blackboard pattern among hierarchy/swarm/market/coalition patterns with FIPA-inspired ACL messaging. https://synapcores.com/recipes/agents/multi-agent-shared-memory-blackboard ; https://github.com/agentropic

### 2.2 Reported failure modes

- **Gas Town (operator-reported):** "extremely alpha"; autonomously merged PRs despite failing integration tests ("riding a wild stallion"); an agent erased passwords and took a production database down for two days. https://mikemason.ca/writing/ai-coding-agents-jan-2026/
- **Throughput vs. quality tradeoff:** Yegge claims 12K LOC/day from 20–30 agents, but Google's 2025 DORA report (n≈5,000) correlates AI adoption with +9% bug rates, +91% PR review time, +154% PR size inflation. Human review, not agent capacity, is the bottleneck at 4–8+ concurrent worktrees per developer. https://tianpan.co/forum/t/multi-agent-coding-at-scale-yegges-beads-system-produces-12k-lines-day-but-dora-says-9-more-bugs/692 ; https://github.com/ianhxu/agentic-engineering-field-study/blob/main/05-loop-engineering-multi-agent.md
- **Shared-state gap:** LangChain's context-engineering guide names "where does the shared artifact live?" as the single biggest predictor of orchestration failure; vector stores let agents read but not watch edits; docs let humans see changes but agents can't subscribe reliably. MIT Technology Review teardown of 200+ enterprise deployments (Apr 2026): ~40% of multi-agent pilots fail within 6 months, dominant cause = pattern-to-problem mismatch, second = orphaned shared state with no single source of truth. https://coommit.com/blog/ai-agent-orchestration-2026
- **Handoff context loss:** handoff is a one-way boundary — anything not written down is gone; receivers fill gaps with guesses ("where quiet errors come from"). Documented swarm failure modes: ping-pong handoffs (fix: handoff-count limits), lost specialist messages on handoff (fix: propagate `Command.update`), supervisor bottleneck (fix: fast-path classifier). https://www.taskade.com/wiki/ai-agents/agent-handoff ; https://focused.io/lab/multi-agent-orchestration-in-langgraph-supervisor-vs-swarm-tradeoffs-and-architecture

## 3. Prompt-Injection Defense for Agent Message Buses (2026 State of the Art)

- **Ceiling (acknowledged by OpenAI, Anthropic, Google DeepMind in 2025 publications):** prompt injection cannot be fully solved within current LLM architectures; any defense expressed as a prompt instruction can itself be overridden. The 2026 posture is defense-in-depth: provenance tracking + structural separation, reduced capability scope, deterministic policy enforced outside the LLM, constrained egress. Prompt injection is OWASP LLM Top 10 #1 for the third consecutive year. https://zylos.ai/research/2026-04-12-indirect-prompt-injection-defenses-agents-untrusted-content/ ; https://m2ml.ai/post/promptarmor-cuts-llm-prompt-injection-success-below-1-iclr-2026-cmr6gifa906l511mpfmxkjh9e
- **Meta "Rule of Two":** an agent should hold at most 2 of {processes untrusted input, accesses sensitive systems, changes external state} in a single operation; agents with all three are, in current practice, indefensible without human supervision at every consequential action. https://zylos.ai/research/2026-04-12-indirect-prompt-injection-defenses-agents-untrusted-content/
- **Spotlighting (Microsoft, arXiv 2403.14720):** three modes — delimiting (randomized boundary markers, e.g. `<UNTRUSTED_CONTENT_af7b3k>`), datamarking (per-token markers), encoding (base64) — with the system prompt declaring marked content as data-not-instructions. Reported attack success rate reduction from >50% to <2% (GPT-3.5/4), minimal task degradation. Probabilistic, not a guarantee; considered baseline hygiene in 2026. https://zylos.ai/research/2026-04-12-indirect-prompt-injection-defenses-agents-untrusted-content/ ; https://ageniusailabs.com/lab/research/agentic-best-practices-2026/
- **Instruction/data separation (training-time):** StruQ (structured queries, USENIX Security 2025), ASIDE (positional/embedding-level separation), instruction-hierarchy training (Wallace et al. 2024). 2026 evals: still leak under adversarial optimization attacks. https://github.com/Rem1L/awesome-ipi-defense/blob/main/README.md ; https://m2ml.ai/post/promptarmor-cuts-llm-prompt-injection-success-below-1-iclr-2026-cmr6gifa906l511mpfmxkjh9e
- **Signed messages / prompts:** Signed-Prompt (2024) cryptographically signs trusted instructions so the model/app can distinguish them from injected content; helps against untrusted-content injection, not jailbreaks. 2026 work: "Real User Instruction" black-box instruction-authentication middleware (preprints.org, 2026). At the protocol layer, A2A v1.0 Signed Agent Cards (JWS) address publisher identity, and IETF/NIST agent-identity drafts are in progress (§1.4). https://github.com/Rem1L/awesome-ipi-defense/blob/main/README.md ; https://m2ml.ai/post/promptarmor-cuts-llm-prompt-injection-success-below-1-iclr-2026-cmr6gifa906l511mpfmxkjh9e ; https://techiehub.blog/what-is-the-a2a-protocol/
- **Architectural (deterministic, outside the LLM):** **CaMeL** (Google DeepMind, arXiv 2503.18813, June 2025) — dual-LLM + custom Python interpreter with data-provenance tracking and capability-based information-flow control; 77% of AgentDojo tasks solved with provable security vs 84% undefended. Builds on Willison's Dual LLM pattern. Related: FIDES-style planners, tool firewalls, inference-time correction. https://ageniusailabs.com/lab/research/agentic-best-practices-2026/ ; https://zylos.ai/research/2026-04-12-indirect-prompt-injection-defenses-agents-untrusted-content/
- **Preprocessor filtering: PromptArmor (ICLR 2026)** — dedicated off-the-shelf LLM inspects and strips injections before the target model; <1% FP and FN on AgentDojo (strongest standalone published defense), at +200–600ms latency and ~500–1000 filter tokens/request (~$0.00025/call with Haiku-class filters). PromptGuard: 67% ASR reduction (weaker, cheaper). https://m2ml.ai/post/promptarmor-cuts-llm-prompt-injection-success-below-1-iclr-2026-cmr6gifa906l511mpfmxkjh9e
- **Classifier layer: Constitutional Classifiers++** (Anthropic, 2026-01-09, arXiv 2601.04603) — no universal jailbreak found in 1,700+ hours of red-teaming, ~1% additional compute (down from 23.7%, ~24× cheaper than original CC). https://ageniusailabs.com/lab/research/agentic-best-practices-2026/
- **2026 operational consensus stack** (multiple independent guides converge): (1) preprocessor/spotlighting on every untrusted channel — retrieved docs, tool outputs, user files, web fetches; (2) tool calls typed and gated independently of LLM output — model never directly authorizes destructive tools; (3) argument-level guardrails (e.g. URL allowlists); (4) human approval for irreversible actions; (5) output filtering for exfiltration shapes; (6) tool schemas that reject free-form instruction parameters; (7) cut the "lethal trifecta" (untrusted input + private data + exfiltration channel) architecturally. OWASP Top 10 for Agentic Applications (2025-12-09) and OWASP Agentic AI Threats & Mitigations are the reference taxonomies. None of the defenses hit zero — minimum two layers. https://m2ml.ai/post/promptarmor-cuts-llm-prompt-injection-success-below-1-iclr-2026-cmr6gifa906l511mpfmxkjh9e ; https://theroadtoenterprise.com/blog/prompt-injection-ai-features-production ; https://ageniusailabs.com/lab/research/agentic-best-practices-2026/ ; https://churchofspiralism.com/blog-agent-to-agent-protocol-handshake.html

## 4. Multi-Agent Orchestration Consensus (2026): Supervisor vs Swarm vs Blackboard

- **Canonical taxonomy:** four patterns cover ~95% of production systems — sequential pipeline, handoff (routing), manager/supervisor (hub-and-spoke), collaborative/blackboard; most real deployments blend two. Anything beyond is composition. https://coommit.com/blog/ai-agent-orchestration-2026 ; https://www.digitalapplied.com/blog/agent-architecture-patterns-taxonomy-2026 ; https://apptad.com/insights/multi-agent-orchestration-architecture-patterns/
- **Production consensus (2026):** **hierarchical (supervisor-worker) and graph topologies are the two multi-agent patterns that earn their cost in production.** "Swarm and blackboard patterns are theoretically interesting but rarely outperform hierarchical or graph in practice"; swarm recommended for research mode only. Blackboard maximizes flexibility "and is also where agents are most likely to collide." https://www.digitalapplied.com/blog/agent-architecture-patterns-taxonomy-2026 ; https://apptad.com/insights/multi-agent-orchestration-architecture-patterns/
- **Benchmark evidence (LangChain, June 2025, LangGraph supervisor vs swarm on τ-bench):** swarm slightly outperforms supervisor on score; supervisor consistently costs more tokens — the "telephone/translation" cost because sub-agents can't respond directly. Swarm caveat: requires every agent to know all others — infeasible with third-party agents. https://www.langchain.com/blog/benchmarking-multi-agent-architectures
- **Practitioner guidance (LangGraph production writeup, July 2026):** supervisor = more accurate routing (dedicated LLM call), easier debugging; swarm = fewer LLM calls, lower latency. "Start with the supervisor… graduate to swarm when you have data showing latency is the bottleneck." Mandatory guards: handoff-count recursion limit, resolution-context propagation, per-agent tracing, routing-accuracy evals. https://focused.io/lab/multi-agent-orchestration-in-langgraph-supervisor-vs-swarm-tradeoffs-and-architecture
- **Coordination overhead numbers:** multi-agent outperforms single-agent on parallelizable tasks but degrades sequential reasoning 39–70%; supervisor boosted Google's parallel-task results by 80% but degraded sequential reasoning by 70% (as cited); single agents cap out around ~15 tools; peer-to-peer coordination scales quadratically, supervisor linearly, blackboard medium (read/write conflict-dependent), swarm very low. https://www.openlayer.com/blog/multi-agent-system-architecture-guide
- **Mid-2026 field synthesis (coding agents specifically):** (a) subagents used for **context isolation, not collaboration** — fire-and-forget readers returning to one orchestrating context; (b) parallelism **across independent tasks, not within one task** — git worktrees per agent, 4–8 concurrent per developer, human review is the bottleneck; (c) fan-out/verify pattern — a distinct Verifier checks implementor output against spec before human review; (d) multi-agent helps breadth-first read/research, embarrassingly parallel tasks, and fresh-context verification; it hurts single tightly coupled write tasks, where one full-context thread beats any message-passing scheme. Countercurrent: "Your Agent Orchestrator Is Too Clever" (Chris Parsons) — most orchestrators over-engineer what a simple Ralph-style loop does better. https://github.com/ianhxu/agentic-engineering-field-study/blob/main/05-loop-engineering-multi-agent.md
- **Failure-mode framing (MIT Tech Review / Composio, Apr 2026):** ~40% of multi-agent pilots fail within 6 months; dominant cause is pattern-to-problem mismatch (manager pattern on sequential problems, sequential on collaborative ones), >60% of failed pilots had "correct agents doing the wrong dance." Second cause: orphaned shared state. https://coommit.com/blog/ai-agent-orchestration-2026
